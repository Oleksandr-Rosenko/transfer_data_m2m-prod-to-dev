# Перенос повідомлень Prod → Dev (M2M)

Streamlit-застосунок: беремо повідомлення об'єкта з Prod (`my.m2m.eu`) і «програємо» їх на dev-сервер так,
ніби їх надсилає трекер. Потрібен розробникам, щоб тестувати на реальних даних.

## Як користуватись

1. Бічна панель: увійдіть на Prod (логін і пароль живуть лише в сесії браузера й ніде не зберігаються).
2. **Об'єкт-джерело**: пошук за назвою або IMEI.
3. **Куди переносимо**: протокол, адреса й порт dev-сервера, IMEI об'єкта на dev (його треба створити заздалегідь).
   Кнопка «Перевірити з'єднання з dev» робить лише handshake, дані не надсилає.
4. **Період** (київський час) і режим часових міток:
   - *зсунути* — кінець періоду стає «зараз мінус N хв», інтервали між точками зберігаються;
   - *залишити оригінальні дати*.
5. **Попередній перегляд**: кількість повідомлень, перше й останнє, графік напруги.
6. «Пробний запуск» надсилає лише перші 20 повідомлень, щоб перевірити, що dev їх приймає.
7. «Почати перенос»: прогрес у відсотках, лічильник повідомлень, швидкість, залишок часу, журнал помилок,
   «Зупинити» та «Повторити невдалі».

> Якщо перенести той самий період двічі, на dev можуть з'явитись дублікати.

## Протоколи

| Протокол | Порт за замовчуванням | Що передається |
|---|---|---|
| Teltonika Codec 8E (рекомендовано) | 5027 | усі сирі IO трекера, ID до 65535 |
| Teltonika Codec 8 | 5027 | те саме, але лише IO з ID ≤ 255 (решта пропускається й показується у звіті) |
| Wialon IPS 2.0 / 1.1 | 5039 | усі параметри точки як є; службові — за галочкою |

Одне TCP-з'єднання на весь перенос; повідомлення йдуть пакетами (за замовчуванням по 100, максимум 255).
Якщо сервер підтвердив лише частину пакета, повторно надсилається тільки решта. Обрив з'єднання — до 3 спроб
з перепідключенням. Якщо перші 3 пакети відхилено повністю, перенос зупиняється з поясненням.

### Які параметри переносяться

У точці на платформі є дві групи параметрів:

- **дані трекера**: `io_<ID>` та іменовані (`power`, `battery`, `ignition`, `rssi`, `odometer`, `operator`,
  `hdop`, `pdop`, ...), які платформа вже перетворила з IO. Для Teltonika вони повертаються в IO за таблицею
  `NAMED_TO_IO` у `m2m_replay/mapping.py` (наприклад, `power` 12.084 В → IO 66 = 12084 мВ);
- **службові параметри платформи**: `pf_*`, `power_enb`, `power_filtered`, `m2m_*`, `distance`, `totalDistance`,
  `_MOTION`. Через Teltonika їх передати неможливо, dev порахує їх сам із вхідних даних.
  У Wialon IPS їх можна передати за галочкою «Передавати й службові параметри».

Координати беруться «сирі», від трекера (`pf_orig_lat/lon`), а якщо їх немає — з точки.
Таблиця `NAMED_TO_IO` складена за документацією Teltonika (серія FMC/FMB) і звірена з вашими CSV-вивантаженнями
(усі ключі розпізнаються, 22 IO). Якщо на dev якийсь параметр з'являється під іншою назвою, виправте ID там.

## Запуск локально

```bash
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # за потреби
streamlit run app.py
```

## Streamlit Community Cloud

1. New app → цей репозиторій, гілка `main`, **Main file path: `app.py`**.
2. App → Settings → **Secrets**: вміст `.streamlit/secrets.toml.example` (адреса й порти dev).
3. Після кожного пушу в `main` застосунок перезбирається сам.

⚠️ Хмара Streamlit ходить на dev з публічних адрес. Якщо порт 5027/5039 відкритий лише для певних IP,
кнопка «Перевірити з'єднання з dev» покаже помилку підключення: тоді відкрийте порт або запускайте застосунок
на машині всередині мережі.

## Структура

```
app.py                  інтерфейс (2 екрани: налаштування і прогрес)
m2m_replay/
  client.py             API платформи: вхід, пошук об'єктів, точки за період (паралельне завантаження сторінок)
  models.py             Point, розбір часу й атрибутів
  mapping.py            відповідність параметрів платформи ↔ IO / параметри Wialon
  teltonika.py          кодування Codec 8/8E, відправник
  wialon.py             кодування IPS 1.1/2.0, відправник
  replay.py             фонове завдання, зсув часу, пакети, повторні спроби, попередній перегляд
tests/                  модульні й наскрізні тести (мок-сервери Teltonika і Wialon)
```

## Тести

```bash
python -m unittest discover -s tests -v     # або: pytest
```

Що перевірено: CRC і байти пакета Codec 8 збігаються з офіційним прикладом Teltonika; незалежний декодер
розбирає Codec 8 і 8E; повний перенос через мок-сервери (час, порядок, ID > 255, часткові ACK, обрив і перепідключення,
відмова сервера, невідомий IMEI, зупинка, повторення невдалих); мапінг усіх ключів із реальних CSV.

Що **не** перевірено автоматично: прийом на справжньому dev-сервері (особливо Wialon IPS: специфікацію реалізовано,
але проти реального сервера не запускали) та сам інтерфейс у справжньому Streamlit. Тому перший раз використайте
«Пробний запуск» і подивіться результат на dev.
